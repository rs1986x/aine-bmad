## Deferred from: code review of 2-2-create-a-todo (2026-07-13)

- `addTodo`'s immutable prepend can be overwritten or duplicated by a concurrent `reload()` — the reload effect replaces the whole list from the server, and there is no de-dup by `id`, so a create resolving around a reload can lose the new item (server overwrite) or surface it twice. No auto-reload exists today (reload fires only from the load-error branch, where the form is unmounted), so the window is currently unreachable; tied to the accepted 1.4 reload/AbortController deferral. Revisit with the full reliability UX in Story 2.5. [frontend/src/hooks/useTodos.ts]
- Zod `.max(500)` measures UTF-16 code units while the DB `CHECK (char_length BETWEEN 1 AND 500)` measures Unicode code points, so a description of astral-plane characters (emoji, some CJK extensions) near the boundary is rejected as ">500" before the DB would accept it — the "500-character" limit is inconsistent with what the user perceives. Low impact; the DB remains the backstop. Consider a code-point-aware length check if this matters. [backend/src/schemas/todo.schema.ts]
- Zero-width / other non-trimmable Unicode (e.g. `U+200B` zero-width space) passes `.trim().min(1)` on both client and server and persists a visually-blank todo, since JS `String.prototype.trim()` does not strip those code points. Edge case, low impact; revisit if visually-empty todos become a real problem. [backend/src/schemas/todo.schema.ts, frontend/src/components/AddTodoForm.tsx]
- A NUL byte (`\u0000`) in `description` passes Zod's `.trim().min(1).max(500)` (a valid non-empty JS string) but Postgres rejects NUL in `text`, so the pg driver throws a non-`AppError` and `errorHandler` maps it to a generic `500` rather than the `400 VALIDATION_ERROR` envelope AC #4 expects for invalid input. Rare input; a Zod `.refine`/regex to reject control chars belongs with the broader input hardening in Story 2.5. [backend/src/schemas/todo.schema.ts, backend/src/repositories/todo.repository.ts]
- `createTodo` (and `getTodos`) do not wrap the success-path `await response.json()`, so an empty or non-JSON 2xx body throws a raw `SyntaxError` that bypasses the `isTodo`/array shape guards and surfaces as an uncontrolled rejection. Consistent across both clients and unreachable while the server always returns JSON; wrap both in a try/catch → typed `ApiError('malformed_response')` during the 2.5 reliability pass. [frontend/src/api/api.ts]
- Enter that commits an IME composition (CJK and other composed input) triggers the form's `onSubmit` prematurely because the handler does not check `e.nativeEvent.isComposing`. i18n edge, low impact; add an `isComposing` guard when internationalizing input handling. [frontend/src/components/AddTodoForm.tsx]
